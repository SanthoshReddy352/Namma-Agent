# OCR for Automatic Exam-Sheet Grading — Technology Research & Analysis

**Purpose:** Select OCR/HTR technology for extracting text from handwritten + printed exam answer booklets (≈32 pages each) with high accuracy and low cost, for an AI grading pipeline built in modules.

**Date:** 06 August 2026 · **Author:** Namma Agent research

---

## 1. TL;DR — Bottom Line

| Need | Best pick | Per-booklet cost (32 pages) |
|---|---|---|
| **Lowest cost + good handwriting (recommended default)** | **PaddleOCR PP-OCRv5 (local, self-hosted)** | ≈ **$0.001–0.005** (rented GPU) / ~₹0 |

**Key insight:** Tesseract is free but scores only ~30% on handwriting — unusable for answer sheets. PaddleOCR PP-OCRv5 is also free but is the strongest local option for handwriting (26% fewer recognition errors than the previous version), supports 80+ languages incl. Telugu, and runs on a CPU if needed. If you must use a third-party API, all the big clouds charge the same **$1.50 per 1,000 pages** for plain OCR → **$0.048 per 32-page booklet**; Gemini's free tier (1,500 pages/day) makes it effectively ₹0 at pilot scale.

## 2. The OCR Landscape (three generations of technology)

1. **Classic pipeline OCR** — Tesseract. Rule/LSTM-based, CPU-first. Great for clean printed text, near-useless on handwriting.
2. **Deep-learning pipeline OCR** — PaddleOCR, EasyOCR, DocTR, TrOCR, Surya. Separate detect → recognize stages (or full-page transformers). This is where handwriting got practical.
3. **VLM / end-to-end OCR** — Qwen2.5-VL, DeepSeek-OCR, olmOCR, GOT-OCR 2.0, PaddleOCR-VL, Chandra, plus closed APIs (GPT-4o, Gemini, Mistral OCR). One model reads the page end-to-end, understands layout, can emit Markdown/JSON. Most powerful, most GPU-hungry.

For answer sheets (handwriting-dominant), the sweet spot is **generation 2 for local, generation 3 for cloud**.

### Local cost for a 32-page booklet
- **Marginal cost ≈ ₹0** — you pay for hardware, not pages.
- On a rented GPU (RTX 4090 ≈ $0.4–0.7/hr, A100 ≈ $1.5–3/hr): PaddleOCR ~0.2–0.5 s/page → 32 pages in ~10–20 s → **< $0.005/booklet**.

## 5. Handwriting Accuracy Evidence

- **Real-world answer-sheet test** (Eklavvya, 50 sheets, 2025): Tesseract ≈ **30%** accuracy on handwriting → most sheets need manual rework; **Google Vision ≈ 90%** (95% clear handwriting, ~80% poor handwriting). EasyOCR in between.
- **IAM handwriting benchmark** (13,353 lines, English): best published line-level results — **GPT-4o-mini WER 3.34**, HTR-JAND (specialized HTR, lexicon-corrected) WER 3.78, MetaWriter WER 10.3; classic TrOCR-era models sit at WER ~15–20. → On clean, line-segmented English handwriting, small VLMs now beat dedicated HTR models.
- **PaddleOCR 3.0**: 96.3% on OmniDocBench v1.6 (mixed printed docs); PP-OCRv5 reduces error rate **26%** on non-standard handwriting vs PP-OCRv4.
- **Surya**: 83.3% olmOCR-bench (top sub-3B model), 87.2% on 91-language benchmark.

**Practical reality check:** no off-the-shelf engine reads arbitrary messy student cursive perfectly. Expect 85–95% word-level accuracy on decent handwriting with the best options, lower on poor handwriting. A grading pipeline should therefore treat OCR output as *noisy evidence* — combine with keyword/answer matching, fuzzy scoring, and confidence thresholds that flag low-confidence regions for human review rather than failing silently.

| Engine/API | Telugu support | Handwritten Telugu quality |

| Tesseract | Yes (traineddata) | Weak on handwriting |
| EasyOCR | Yes | Weak |
| Surya | Yes (91-lang benchmark) | Moderate |
| Google Vision / Gemini / Azure | Yes | Moderate — cloud models trained on far more data |
| TrOCR | **No** (English only) | — |

If handwritten Telugu is a large share of content, plan to **fine-tune** a recognition model (PaddleOCR or TrOCR-style) on a few hundred labelled Telugu answer-sheet lines — this is the single biggest accuracy lever for regional scripts.

## 7. Recommended Module Architecture (plugs into your grading front-end)

```text
Scanned page (300 DPI, grayscale)
        │
        ▼
1. Preprocessing        deskew, denoise, contrast, remove background grid
        │
        ▼
2. Line/region detection   PaddleOCR det  OR  Surya layout
        │
        ▼
3. Recognition
   ├─ Printed headers/questions → PaddleOCR PP-OCRv5 rec (multilingual)
   └─ Handwritten answers      → PaddleOCR rec (handwriting model)
                                 or TrOCR-large-handwritten (clean English lines)
        │
        ▼
4. Confidence scoring + post-processing
   spell-correct, keyword normalization, math/formula note
        │
        ▼
5. Low-confidence regions → flag for review OR re-run on Gemini free tier / Vision API
        │
        ▼
6. Structured output (per page: question no., text, confidence) → grading modules
```

**Cost of this stack:** local PaddleOCR ≈ $0.001–0.005/booklet on rented GPU; even with a 10% fallback to Gemini, total < $0.01/booklet.

## 8. Recommendations

1. **Default: self-hosted PaddleOCR PP-OCRv5** — free, best local handwriting + Telugu support, huge ecosystem, deployable on CPU or GPU. Run it in a Docker container exposing a small API so your grading front-end treats OCR as a black-box module.
2. **Accuracy ceiling on English handwriting:** fine-tune TrOCR (or use GPT-4o-mini) on your own labelled lines if budget allows — expect the biggest WER drop.
3. **Simple-but-good cloud option:** Google Cloud Vision at $0.048/booklet (first 1,000 pages free) or Gemini 2.5 Flash-Lite (1,500 pages/day free) — zero infrastructure, ~90% handwriting accuracy out of the box.
4. **Avoid:** Tesseract for handwriting (30% is a dead end); Textract/Azure only if you're already inside AWS/Azure and want their structured features; per-page APIs for bulk volumes (local is 10–100× cheaper at scale).
5. **Data privacy:** student answer sheets are sensitive — local-first keeps data on-prem (relevant under India's DPDP Act). Cloud APIs are the pragmatic choice only for pilots or as a fallback.
